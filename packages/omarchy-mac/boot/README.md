# Apple boot support

This subtree is built into `omarchy-mac-boot`, separately from the kernel-neutral `omarchy-mac` hardware package. `../install` intentionally does not stage this directory. The boot recipe pins a runtime revision, the same one as the desktop candidate, and stages this subtree from it; the recipe keeps only packaging metadata and the pacman scriptlet.

`install DESTDIR` stages commands in `/usr/bin`, sourced modules/setup leaves in `/usr/lib/omarchy-mac/boot`, and the initramfs, in-place encryption and first-boot payload in `files/` at its installed paths (mkinitcpio drop-ins, initcpio hooks, units, presets, the ALPM hook and `/etc/default/update-m1n1`, which pins update-m1n1's device-tree order to the C locale). It performs no live setup. The recipe's `backup=` covers every `files/etc` path and `files/usr/lib/omarchy/initcpio`. `test/all` runs command fixtures and the payload's offline checks; `OMARCHY_DISPOSABLE_BOOT_TESTS=1` also builds real initramfs images and converts loop-device disks in privileged containers. Shared provisioning/reset integration remains covered by the runtime suite.

The implementation was moved from runtime integration `e82fe3c8850b184dfa22eefd571646ad85446122`, preserving Marcelo's provenance recorded in the runtime source-port ledger. The payload in `files/` comes from the boot recipe paired with #503 (omarchy-mac/omarchy-pkgs-aarch64#65 at `617a907f99a1`) with maralcbr/omarchy-pkgs#202 applied (omarchy-mac-boot 20260921-10: the owner's keyboard layout and dock keyboards at the disk prompt). The owner wizard, recovery-slot operations, journal/retry handling and shared Limine menu/hash operations remain core code. Provisioning and reset refuse to proceed on Apple Silicon when their required package module is unavailable.

## Temporary adaptations

- Deploy ARM64 Limine to U-Boot's `EFI/BOOT/BOOTAA64.EFI` slot until the shared Limine installer supports that target.
- Retain the current GRUB-defaults-to-`rd.luks.*` command-line bridge while conversion, rekey and reset share that protocol. Switching to Limine does not itself change the initramfs unlock protocol. Removing this bridge requires coordinated conversion/rekey/reset qualification.
- Check factory-kernel coherence against the live boot partition because firmware, m1n1/U-Boot and DTBs are outside root snapshots. Generic root snapshot restoration alone cannot establish boot compatibility.

Do not duplicate shared snapshot/UI/password policy here. Historical GRUB fallback remains for compatibility; this refactor qualifies fresh Limine images, not upgrades of old factory snapshots. Old-quattro migration is separately designed and tested.

## Migration

`omarchy-mac-migrate` moves an existing Mac onto a target package set in place (spec: Migration). The upstream migration `migrations/1790347292.sh` reaches it through `omarchy-lifecycle-dispatch migrate` (`entrypoints/migrate`), and it can be run directly: `sudo omarchy-mac-migrate status | run [--target FILE] | verify`. `lib/migrate-engine.sh` is the engine; each cohort has an adapter beside it (`lib/migrate-tester.sh` for quattro-upstream testers; mx-mac and legacy omarchy-mac are tickets 43 to 45 and are refused until then).

- **Target:** a root-owned key=value file: `--target`, else `/etc/omarchy-mac/migration-target`, else `/usr/lib/omarchy-mac/boot/migration-target`, which no package ships yet. Without one the command does nothing. `type=candidate-set` points at a signed test candidate set (`set=DIR` with its `manifest.json`, `signing.json` and signatures, `fingerprint=` its signer) and verifies it as `tools/release/candidate-set verify` does. `type=repository` points at an official `[omarchy]` channel. Both give `channel=` and optionally `server=`.
- **Steps:** preflight, backup, keyring, prefetch, repositories, transaction, boot-chain, loader, reboot, retire. Each step's start and end go to `/var/lib/omarchy-mac/migration/journal`, synced, and a run resumes at the first step without an end. Every step can run again from its start. Preflight refuses unsupported states before anything changes, then freezes the plan in `plan/`. Backups go to `backup/` (root only): cached package files, `/etc`, `/boot`, the ESP and the LUKS header, with `SHA256SUMS`.
- **Packages:** prefetch downloads everything into its own cache with the future configuration and a copy of the package database, then rehearses the transaction with `--dbonly` (no files, scriptlets or hooks). The rehearsal may remove only what the adapter allows. The transaction reuses those databases and that cache without syncing again, names each target in its repository so a higher installed version is replaced, and must end exactly where the rehearsal did. A candidate set is served to pacman as a local repository in the transaction's configuration only. Its key never enters pacman's keyring.
- **Boot:** the stage-two image (m1n1, device trees, U-Boot) and the GRUB or Limine menu are rebuilt and checked with the boot check's pending-reboot mode before the loader changes. A GRUB Mac is switched by `setup/limine-boot.sh`, which restores what it touched on failure. After the reboot, `omarchy-mac-migrate-verify.service` (enabled only while a reboot is pending) requires Aurora running through the packaged Limine and a clean boot check before retiring anything.
- **Activation order:** the migration marks itself done the first time it runs. Wherever it runs before a target is set, it does nothing and never runs again. So the build that first carries the migration to users must also carry its target (ticket 53).
