## Validation

With the pinned companion checkout at `../omarchy-pkgs`:

```bash
export OMARCHY_PKGS_PATH="$(cd ../omarchy-pkgs && pwd)"
./test/all
./tests/all
bin/omarchy commands --check
```

Also run the shebang-aware syntax and ShellCheck checks in `.github/workflows/main.yml`. The real-pacman transaction fixture tests unchanged packages, selected upgrades and downgrades, ordinary system upgrades, and reproduces the original failure without protection. It runs on hosts with pacman and inside the ARM install harness.

On a disposable ARM machine with the documented root/nspawn requirements, run `test/vm/run-selective-edge` with `OMARCHY_PKGS_PATH` set to the pinned recipes and both `OMARCHY_INSTALL_VM_PACKAGE_SOURCES=1` and `OMARCHY_INSTALL_VM_IDEMPOTENCY=1`. Preserve those variables through sudo. Use the hosted ARM workflow when local passwordless sudo is unavailable. Its package-source assertions must remain exact.

## Remaining release gates

A locally passing suite is not a passing hosted ARM installation or release qualification. Before an RC: obtain green integrated CI, isolate ARM RC from existing stable clients, freeze published artifacts and ISO inputs, and qualify published-package upgrades and fresh encrypted installs on M1/M2. Keep M3 experimental. Passwordless sudo expiry across reboot remains a separate security qualification gap; #376 addresses scheduling failure only. No running desktop configuration, package installation, or disk layout should be changed as part of this integration validation.
