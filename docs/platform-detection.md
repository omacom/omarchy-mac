# Platform detection and bootstrap

Architecture, Apple identity, portable hardware, bootloader and filesystem answer different questions. Select package repositories and executable architecture with `omarchy-hw-arch`, which prints only `x86_64` or `aarch64` and accepts `arm64` as an alias. Unsupported architectures and failed `uname` calls return failure without a canonical name. Before an architecture-dependent mutation, capture that result and stop on failure; a false `omarchy-hw-aarch64` result is not proof of x86. The Boolean detectors share the canonical detector through their own directory so they also work before the checkout is on PATH.

`omarchy-hw-apple-silicon` requires ARM architecture and an actual `apple,` entry in the NUL-separated device-tree compatible list. It selects Apple-specific driver and userspace fixes, not every ARM machine. It does not determine whether the machine is a laptop. `omarchy-hw-laptop` recognizes ACPI lid entries, portable DMI chassis types, portable device-tree `chassis-type` values, or an input device advertising `SW_LID`. Desktop, all-in-one, missing and unknown firmware chassis descriptions do not become laptops merely because their vendor is Apple. The implementation has no board list. Tests use isolated paths for all firmware and input metadata; physical evidence so far is limited to the j313 host.

Device-tree `chassis-type` is standardized in [dt-schema's root-node schema](https://github.com/devicetree-org/dt-schema/blob/main/dtschema/schemas/root-node.yaml). Linux declares `laptop` for the [M1 MacBook Air j313](https://github.com/torvalds/linux/blob/master/arch/arm64/boot/dts/apple/t8103-j313.dts) and `desktop` for the [M1 Mac mini j274](https://github.com/torvalds/linux/blob/master/arch/arm64/boot/dts/apple/t8103-j274.dts). `SW_LID` is the lid-switch capability from [Linux's input event codes](https://github.com/torvalds/linux/blob/master/include/uapi/linux/input-event-codes.h). These properties describe the hardware without embedding Apple model names in detection code. `LidClosed=false` alone cannot establish that a machine has a lid.

Boot operations retain their own concrete checks: GRUB layout, ESP filesystem and mount locations, root filesystem and subvolume structure. Architecture does not establish that Limine is installed or that a Btrfs root exists. The phase-one factory-reset backend guard, Snapper-on-Btrfs behavior and existing memory policy remain separate from platform detection.

The root `install.sh` dispatches canonical ARM to `install/aarch64/install.sh`, whose checkout is two directories above its own file. Both dispatcher and child put the checkout's `bin/` first. The package builder invokes its detector by checkout path. The non-Apple ARM installer path remains experimental and warns; it is used by isolated ARM userspace CI and is not a declaration of generic ARM hardware support.

The documented downloaded entrypoints are a deliberate exception to using installed detector commands: both Quattro upgrade scripts, `omarchy-system-boot-to-esp`, `omarchy-system-btrfs-migrate`, the guided `omarchy-mac-setup`, and `omarchy-pkg-publish-aarch64` can run before a new checkout or helper exists. Their self-contained architecture guards must check `uname`'s exit status before interpreting its output. The standalone Mac upgrade retains its device-tree warning. The publisher checks architecture only when building; its `--from` mode accepts archives built elsewhere. Keep these exceptions narrow; normal runtime and hardware leaves use the shared detectors. Historical migration checks are retained as shipped.

`omarchy-pkg-add` retains upstream's required-package contract on every architecture: pass the requested names to pacman and verify they are installed. Missing repository entries and failed transactions are errors. Package-name substitutions belong to their caller, such as selecting `obsidian-appimage` instead of `obsidian` on ARM, rather than silently filtering arbitrary requests in the shared helper. The default installer also recognizes already installed local archives before asking an AUR helper to resolve them.
