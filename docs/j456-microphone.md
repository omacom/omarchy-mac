# J456 iMac microphone fallback

The existing `omarchy-asahi-mic.service` provides a single-channel fallback for the four-port M1 iMac J456 when no native Asahi microphone DSP source exists. It discovers the ALSA capture node by `alsa.id=AppleJ456HPAI`, `alsa.driver_name=snd_soc_aop`, three channels and the exact AUX0/AUX1/AUX2 output layout. Other iMac models are not enabled by this change. Its target is the current PipeWire object serial, not an ALSA card number or an instance-specific node name.

The filter selects AUX2, applies a 100 Hz high-pass filter (Q 0.707) followed by two 10× gain stages (40 dB total), and exposes a mono source named `omarchy_j456_microphone`, displayed as “iMac Built-in Microphone.” On the tested J456, AUX0/AUX1 were substantially weaker, and AUX2 with these settings produced successful speech transcription. The owner confirmed normal Voxtype dictation with the equivalent local filter. This is not a calibrated array profile or beamformer; room noise, distance and loud speech need broader hardware testing. The fixed gain can amplify noise or clip louder input. Reduce the source volume when necessary; the filter does not include automatic gain control or a limiter.

The source has low session priority. The supervisor selects it only if the raw J456 input was already the default; existing USB, headset and custom microphone selections are preserved. It does not reroute running application streams, change physical input gains, or alter any speaker or kernel configuration. Users who selected another input can select “iMac Built-in Microphone” in their usual audio controls.

The watch process owns a `pipewire -c` child using `default/pipewire/j456-microphone.conf` rendered into a private temporary runtime directory. The source is usable only after AUX2 is linked to the filter. The same watcher repairs daemon or device loss, replaces a stale target serial, and stops its child on shutdown. Source gain and mute are persisted in `$XDG_STATE_HOME/omarchy/j456-mic-gain.json` (default `~/.local/state/omarchy/j456-mic-gain.json`), periodically, on graceful shutdown and through the existing `--save-state` audio restart hook. Abrupt process termination can lose changes since the last save.

If a native `effect_output.j<number>-mic` source becomes available, the watcher removes its fallback and leaves native DSP handling to the existing Asahi stereo mapping. It changes the default in this transition only when its own fallback was selected. An independently created source using the fallback's reserved name is left untouched.

No new persistent PipeWire config or service is installed. Existing installations receive this behavior when the shipped microphone watch command is updated and `omarchy-asahi-mic.service` next starts. The one-shot repair invocation continues to defer when native DSP is absent; the long-running watch service owns this fallback. To disable the whole Omarchy microphone mapping for troubleshooting, stop and mask the user service with `systemctl --user mask --now omarchy-asahi-mic.service`; to restore it, unmask and start the same unit. This also disables the existing native DSP stereo mapping.

## Validation

`test/shell.d/j456-microphone-test.sh` exercises hardware/channel gates, a changed instance name and serial, source readiness, source choice preservation, native DSP takeover, child loss and gain/mute recovery without touching the active desktop. `test/shell.d/asahi-mic-map-test.sh` retains coverage of the native DSP mapper. Real PipeWire filter loading and AUX0/AUX1/AUX2 capture links were also checked on J456 with a temporary second filter; the user's existing microphone remained selected. Login, suspend/resume, full audio daemon restart and louder speech still need end-to-end hardware testing of the integrated supervisor.
